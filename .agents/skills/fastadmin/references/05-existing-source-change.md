# 已有源文件修改

## 读取时机

修改已有控制器、模型、服务、验证器、JS、视图、组件，或明确修改插件源文件时读取。

## 目标路径

- 原生已有文件：按当前文件所在目录修改。
- 插件已有文件：修改 `addons/<plugin>` 下目标源文件与必要调用方。
- 新增独立功能默认回到原生新增规则；用户明确要求的插件方案按其指定结构完成。

## 读取上下文

按最小必要范围读取：

- 控制器方法：当前控制器、相关模型/服务、相关 JS/视图、语言包、权限节点。
- 模型或服务：当前模型/服务、调用方控制器、数据库字段、关联模型。
- 验证器：当前验证器、控制器调用场景、表单字段、语言包。
- 前端文件：当前 JS/视图/组件、控制器方法、接口返回格式、语言包。
- 插件源文件：插件当前文件、相邻调用链、插件前端入口、后端组织方式、构建方式。

## 修改规则

- 最小改动；不重排无关代码，不重写无关逻辑。
- 新方法命名、权限判断、参数获取、返回格式、异常处理跟随当前文件。
- 新字段先回到 `references/02-database-design.md`。
- 标准新增管理模块不要塞进已有控制器，回到原生 CRUD。
- 已有控制器加方法后，如需要权限节点，使用最终控制器路径执行 `php think menu --controller=<controller>` 或项目等价命令。
- 插件源文件修改只做必要变更；标记影响范围，避免插件升级后难以恢复。

## 复核

- 新增方法被前端、路由、权限或菜单正确引用。
- 原有方法行为保持不变。
- 模型、服务、验证器、JS、视图、语言包字段一致。
- 插件修改范围符合用户要求，并已说明升级覆盖这些修改的影响。
